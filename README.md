# GamePulse

## Быстрый запуск

Python 3.12+, Docker Compose. Создайте `.env` из `.env.example`:

```powershell
Copy-Item .env.example .env
```

Задайте `ADMIN_TOKEN` (случайная строка), `LLM_API_KEY` и при необходимости `YOUTUBE_API_KEY`. Затем:

```sh
docker compose build
docker compose run --rm --no-deps --user root -v "${PWD}:/setup" -w /setup web python -m app.setup_login
docker compose up -d
```

Открыть: http://localhost:8000, мониторинг: http://localhost:8000/monitor, OpenAPI: http://localhost:8000/docs.

Логин: `admin`, сгенерированный пароль — в `.local-credentials.txt`. Этот файл и `.env` исключены из Git. В `.env` хранится только PBKDF2-хеш пароля; не удаляйте одинарные кавычки вокруг хеша, чтобы Docker Compose не интерполировал символы `$`.

PostgreSQL используется автоматически в Compose. Локальная SQLite нужна для запуска без Docker. `POSTGRES_PASSWORD` следует задать в `.env` при работе вне локальной машины. Порт приложения по умолчанию доступен только на loopback.

### Без Docker / Windows

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.lock
.\.venv\Scripts\python -m pip install --no-deps -e .
.\.venv\Scripts\python -m app.setup_login
.\.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В другом терминале из той же директории:

```powershell
.\.venv\Scripts\python -m app.jobs
```

Воркер и API — отдельные процессы. Работа API без воркера не запускает парсинг. Первый обход начинается сразу после старта воркера, следующий — через час от начала предыдущего. Пропущенные при остановке часы не воспроизводятся пачкой.

### Вход и пароль

Каталог, карточки, мониторинг, API и OpenAPI доступны после входа на `/login`. Пароль проверяется через PBKDF2-SHA256 с индивидуальной солью и 600000 итераций. Сессия хранится в БД как хеш случайного токена; cookie — HttpOnly, SameSite=Lax, срок по умолчанию 12 часов. Выход отзывает сессию в БД. Смена пароля или `SESSION_SECRET` инвалидирует ранее выданные сессии.

После входа кнопка ручного запуска работает без ввода admin-токена: запросы используют CSRF-токен сессии. Для внешнего клиента API остаётся `Authorization: Bearer <ADMIN_TOKEN>`. `/health`, статические файлы и страница входа публичны. Ограничение неудачных входов: 5 попыток за 5 минут с одного IP на процесс. Для публичного размещения за несколькими процессами нужен общий rate limiter и HTTPS; выставьте `COOKIE_SECURE=true`.

Создать новый пароль (заменяет предыдущий; после команды перезапустите web-процесс):

```powershell
.\.venv\Scripts\python -m app.setup_login --username admin
```

### Выбор модели

Активная модель в `.env`: `LLM_MODEL=gpt-5-nano`. Для неё используется `max_completion_tokens=4000` и `reasoning_effort=minimal`; параметр `temperature` не передаётся. Лимит включает внутренние reasoning-токены и видимый ответ. После смены настройки перезапустите воркер. Уже сохранённые резюме не подменяются автоматически; их модель указана в карточке. Команда `app.backfill` пересчитывает их выбранной моделью и кеширует одинаковые отзывы. Сохраняется совместимость со старыми моделями; для GPT-3.5 дополнительно ограничен размер входа с учётом его меньшего контекстного окна.

## Что реализовано

| Требование | Реализация |
|---|---|
| Раз в час, до 20 новых за день игр | Отдельный воркер, состояние расписания в БД |
| Сначала New Releases, затем каталог new | Суточный курсор, сохранение оставшихся ссылок со страницы |
| Ежедневный сброс | Новый курсор по дате в `TIMEZONE`, по умолчанию Europe/Moscow |
| Обновление имеющихся игр | Уникальный slug; карточка, оценки и отметка обработки сохраняются одной транзакцией |
| Название, обложка, описание, разработчик, видео | HTML / JSON-LD адаптер; отсутствующие данные явно отображаются |
| Оценки для каждой платформы | Отдельные строки `platform_ratings`; TBD хранится как NULL |
| Отзывы критиков и пользователей | Раздельный сбор по платформам и раздельный LLM-анализ |
| Каталог, поиск, фильтр, сортировка, карточка | Серверный HTML, SQL-фильтры и пагинация по 20 |
| Похожие игры | Объяснимый рейтинг по жанрам, платформам и разработчику; переход в карточку |
| Доп. 1: летсплей | YouTube Data API, просмотры, субтитры или опциональная локальная транскрибация, LLM-заключение |
| Доп. 2: мониторинг и ручной запуск | SSE, статусы и счётчики запусков; POST с admin-токеном |

Число 20 означает верхний предел попыток в одном обходе. Ошибки повторяются первыми в следующем запуске. Успешно загруженная игра повторно в этот день не выбирается. При исчерпании каталога, лимите страниц или сбоях успешно обработанных игр может быть меньше 20. Суточная дата фиксируется в начале запуска; запуск через полночь завершает старую пачку, следующий начинает новый день.

Оценка для сортировки — максимальная среди выбранных платформ. При фильтре PC используется именно оценка PC, а не максимальная для всей игры. Пропуски располагаются в конце. Рекомендации: Jaccard общих жанров × 0.7 + общая платформа × 0.2 + общий разработчик × 0.1. Для небольшого каталога вычисляются при открытии карточки; для большого каталога их следует предвычислять.

## Архитектура

```text
Browser ── HTTP / SSE ── FastAPI ── SQLAlchemy ── PostgreSQL
                                               ↑
Scheduler / worker ── daily queue ──────────────┤
       ├── Metacritic adapter → card + reviews  │
       ├── LLM adapter → validated summaries ───┤
       └── YouTube → captions / Whisper → LLM ──┘
```

`source.py` изолирует HTML и HTTP. `ai.py` отвечает за LLM и YouTube. `jobs.py` содержит очередь, аренду блокировки и orchestration. `main.py` — HTTP и представления. `transcription.py` — опциональное локальное распознавание. Приём задачи не запускает долгую работу внутри HTTP-запроса.

Очередь, курсор и история находятся в БД. Запуски API и воркеров синхронизируются условным UPDATE одной строки блокировки: одновременно обход выполняет один воркер. Повторный POST возвращает существующий queued-запуск, а во время работы — 409. После аварии процесс восстанавливает pending-записи после истечения аренды `LEASE_SECONDS` (по умолчанию 6 часов). Продление аренды происходит между страницами и играми. Длительность одной игры должна укладываться в аренду; при потере аренды запись результата не выполняется. Это простой однопоточный воркер для тестового задания, без Redis/Celery и распределённого fan-out.

Схема создаётся при первом запуске (`create_all`). Для существующих БД миграций ещё нет: перед развитием схемы нужен Alembic. Не выдаём этот механизм за систему миграций.

## Как используется LLM

- Настраиваемый endpoint, совместимый с `chat/completions`. Ключи находятся в окружении, не попадают в браузер.
- Критики и игроки обрабатываются отдельно. До 40 отзывов по 2500 символов в запросе, до 2 страниц отзывов на платформу по умолчанию. Это ограниченная выборка, а не все отзывы.
- JSON-ответ валидируется Pydantic. Каждый плюс/минус содержит ID подтверждающих отзывов. Неизвестные ID отклоняются. Проверка ID не доказывает семантическую точность модели: подтверждения доступны для проверки человеком.
- Тексты отзывов считаются недоверенными данными. В system prompt запрещено исполнять инструкции из них. Инструментов и секретов в контексте модели нет.
- SHA-256 входа + модель + версия prompt позволяют повторно использовать неизменившийся результат.
- Таймауты, ограниченные повторы 429/5xx, явные статусы отсутствия ключей/отзывов/ошибки. Предыдущий ответ сохраняется в метаданных при ошибке LLM.
- Стоимость ограничена размером выборки, длиной ответа и числом повторов. Ключи и аккаунты пользователь предоставляет самостоятельно. YouTube проверен на настоящем видео; локальное распознавание Whisper пока не запускалось.

Для заполнения анализа уже сохранённых отзывов без повторного сбора игр:

```powershell
.\.venv\Scripts\python -m app.backfill --database-url sqlite:///./gamepulse.db --limit 40
```

Команда использует ключ из `.env`, обрабатывает записи указанной БД, сохраняет результат в карточках и прекращает работу при ошибке API. Уже готовые неизменившиеся резюме переиспользуются без новых платных запросов.

### Летсплеи и распознавание речи

Интеграция подключена к настоящему YouTube Data API и проверена на Enshrouded: найден популярный ролик, получены субтитры и сформировано заключение GPT-5 nano. Ключ передаётся только сервером в `X-Goog-Api-Key`, отсутствует в URL и не выдаётся браузеру. Кеш поиска хранится в `Game.letsplay`; срок обновления — `YOUTUBE_REFRESH_HOURS=24`.

Раздел карточки показывает название видео, канал, число просмотров на момент проверки, ссылку на YouTube, вывод по речи автора и текстовые фрагменты с переходом к соответствующей секунде. Анализ расшифровки получает отдельный контекст одного рассказчика. GPT-5 nano возвращает строгий JSON Schema-ответ, где ID доказательств ограничены реально переданными фрагментами.

Чтобы заполнить или обновить летсплеи существующих игр без повторного сбора Metacritic:

```powershell
.\.venv\Scripts\python -m app.youtube_backfill --limit 40
# Только одна игра:
.\.venv\Scripts\python -m app.youtube_backfill --slug enshrouded --limit 1
```

Операция отображается отдельным запуском в мониторинге, использует общую блокировку с основным воркером и сохраняет каждую карточку по мере готовности. Корректные свежие результаты переиспользуются. `--force` позволяет повторить поиск до истечения кеша. При ошибке ключа или квоты пакет прекращается, предыдущие видео сохраняются. Обычный воркер после quotaExceeded делает паузу в поиске на час, чтобы не повторять ошибочные запросы для каждой новой игры.

Фильтр требует совпадения названия игры целиком с учётом пунктуации и распространённых обозначений изданий; частичного совпадения одного слова недостаточно. Явно помеченные No Commentary / «без комментариев» видео исключаются. Это консервативная эвристика, а не гарантия точной идентификации: для неоднозначных названий лучше показывать отсутствие результата, чем чужую игру.

Отсутствующие субтитры, возрастное ограничение и блокировка выдачи расшифровки явно отображаются. Ключ Data API предоставляет поиск и статистику; он не снимает ограничения доступа к чужим расшифровкам. По словам автора нельзя выдавать заключение, если текст его речи не получен.

Включите YouTube Data API v3 и задайте `YOUTUBE_API_KEY`. Поиск берёт до 25 длинных видео с запросом по названию игры и `lets play walkthrough`, отбирает соответствующие названию, затем выбирает максимальное число просмотров. Это самый популярный среди найденных подходящих результатов, не гарантия наиболее популярного летсплея на всём YouTube. Статистика фиксируется при обходе. Расход квоты зависит от числа игр и вызовов поиска.

Сначала проверяются русские/английские субтитры, затем другие поддерживаемые языки. Если их нет, опционально можно распознать аудио локально:

```powershell
.\.venv\Scripts\python -m pip install -e '.[audio]'
```

Нужен FFmpeg в PATH. В `.env`: `TRANSCRIBE_AUDIO=true`, `WHISPER_MODEL=small`. В Docker дополнительно задайте `INSTALL_AUDIO=true` и пересоберите образ. Whisper скачивает модель при первом запуске. Лимиты — 3 часа и 300 МБ аудио; временный файл удаляется после обработки. CPU-транскрибация может быть долгой и не входит в базовый набор зависимостей. Этот внешний путь не запускался в текущем окружении.

Расшифровка объединяется в последовательные блоки. Если их больше 40, используются равномерно выбранные блоки всего ролика. В карточке доступны текстовые подтверждения и временные отметки. При недоступности аудио/субтитров выдуманное заключение не создаётся.

## Проверки и CI/CD

```powershell
.\.venv\Scripts\python -m pytest -q
.\.venv\Scripts\python -m ruff check app tests
.\.venv\Scripts\python -m ruff format --check app tests
```

Тесты проверяют суточный обход и хвосты страниц, повторы и upsert, блокировку воркеров, ошибки источника, parsing fixtures, API, фильтры, экранирование поиска, авторизацию, валидацию AI и обработку расшифровки. Парсер проверяется как на синтетических случаях, так и на сокращённых реальных HTML-фикстурах Metacritic от 2026-10-15 (`tests/fixtures/metacritic`): платформы, Metascore/TBD, критики, отсутствие пользовательских отзывов и каталог.

### Настоящие обложки

Адаптер извлекает портретное изображение `cardImage` из JSON-данных Nuxt без выполнения JavaScript. Если оно отсутствует, используется изображение из JSON-LD. Картинки сохраняются в `data/covers`, выдаются после входа по `/media/covers/…` и разделяются web/worker через Docker volume `media_data`.

При загрузке проверяются домен источника, допустимый MIME, сигнатура файла и лимит 8 МБ. У некоторых изображений Metacritic MIME `image/jpeg` не соответствует фактическому PNG: локальное расширение определяется по байтам. Это проверено отдельным тестом. Существующие файлы переиспользуются.

Для повторной загрузки обложек существующих настоящих игр:

```powershell
.\.venv\Scripts\python -m app.assets --database-url sqlite:///./gamepulse.db
```

GitHub Actions: lint + форматирование + тесты в матрице SQLite/PostgreSQL + сборка Docker-образа. Внешние API из CI не вызываются. Для локальной проверки PostgreSQL можно задать `TEST_DATABASE_URL` с отдельной БД, имя которой заканчивается на `_test`: тесты пересоздают её таблицы. Production-БД использовать запрещено.

CI подготовлен, но запуск workflow на GitHub и CD в конкретное окружение требуют репозитория и инфраструктуры. Автоматическое развёртывание без заданного сервера и секретов не настроено. Образ и Compose — артефакты для деплоя; после развёртывания проверяется `/health`.
